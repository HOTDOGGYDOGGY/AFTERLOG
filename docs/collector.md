# AFTERLOG Collector (밴드 수집 확장프로그램)

밴드에 로그인한 크롬에서 글·댓글을 모아 `.afterlog` 파일로 저장하는 확장프로그램. 기준 명세: 밴드수집확장 구현명세 v1.1.

## 설치 (지금은 스토어 등록 전)

1. https://hotdoggydoggy.github.io/AFTERLOG/afterlog-collector.zip 받기 → 압축 풀기
2. 크롬 `chrome://extensions` → '개발자 모드' 켜기 → '압축해제된 확장 프로그램 로드' → 푼 폴더 선택
3. 업데이트: 새 zip을 같은 폴더에 덮어쓰고 확장 카드의 새로고침(↻). 수집 중이던 작업·모은 글은 그대로 남습니다.

개발자는 `npm run build:collector` → `dist-collector/`를 로드해도 됩니다.

## 쓰는 법

| 하고 싶은 것 | 방법 |
|---|---|
| 지금 보고 있는 글 하나 | 글을 연 상태에서 확장 아이콘 → **이 글 저장**. 열린 탭은 읽기만 하고 이동시키지 않음 |
| 글 목록 전체 | 밴드 글 목록(또는 멤버 작성글 목록)에서 → **이 목록의 글 모두 저장** |
| 주소 여러 개·기간 | 확장 아이콘 → **수집 관리 열기** → 새 수집 |
| 결과 보기 | 수집 관리 → **.afterlog로 저장** → AFTERLOG 사이트 '프로젝트 → 불러오기' (여러 파트면 모두 함께 선택) |

- 수집용 창을 하나 열고 그 안에서 글을 차례로 엽니다(1.5~3초 간격, 한 번에 하나).
- 수집 관리 창을 닫으면 멈추고, 다시 열어 **이어받기**하면 모은 글은 그대로 두고 남은 것만 이어서 합니다.
- 같은 오류가 서로 다른 글에서 3번 연속 나거나, 로그인이 풀리거나, 처음과 다른 계정으로 보이면 멈추고 이유를 보여 줍니다.

## 권한

| 권한 | 이유 |
|---|---|
| `scripting` | 밴드 화면에서 게시글 영역을 읽기 위해 |
| `unlimitedStorage` | 모은 글·이미지를 브라우저에 보관하기 위해 |
| `https://band.us/*`, `https://www.band.us/*` | 밴드 화면만 |
| `https://*.pstatic.net/*` | 밴드 이미지 파일 받기 |

모든 사이트 접근·탭 목록·쿠키·다운로드 권한은 쓰지 않습니다. 글쓰기·댓글·표정 누르기 같은 동작은 코드에 없습니다.

## 무엇을 저장하나

- 게시글 카드(`.cPostCard`) 영역의 DOM 조각만. 스크립트·이벤트 속성은 지우고 이미지 주소는 절대 주소로 바꿈. 배경 화면·로그인 정보·쿠키는 복사하지 않음.
- 이미지: 받은 바이트가 실제 이미지인지 확인(로그인 화면 HTML을 이미지로 저장하지 않음). `?type=s75` 같은 축소본은 '축소본만'으로 표시.
- 보고서(`capture/report.json`): 목록 끝 판정, 글별 상태, 표시 댓글 수 대비 확보 수, 이미지 실패, 아직 못 하는 것.

## 문제 진단 (개발자에게 보낼 파일)

수집 관리 → 작업 → **문제 진단** → **진단 내용 보기** → 확인 → **진단 파일 저장** (`AFTERLOG_diagnostic_v1.json`).

- 허용 목록 방식: `collector/src/diagnostics/schema.ts`에 선언된 키·열거값·구간만 들어감. 정의되지 않은 키나 자유 문자열이 있으면 저장 자체를 막음(`serializer.ts`). 한글·주소·메일·긴 숫자·토큰 모양이 보이면 한 번 더 막음.
- 들어가는 것: 확장·해석기 버전, 브라우저 종류와 주 버전, 화면 너비 구간, 단계별 상태(화면 인식, 알려진 위치 발견 개수 구간, 필드 있음/없음, 답글 연결, 댓글 수 일치, 첨부 실패 코드, 목록 진전 여부), 대기 시간 구간, 실패한 화면의 **구조 표본**(태그 종류·표준 역할·알려진 위치 ID·텍스트 있음 여부만, 반복 행은 하나로 축약, 깊이 8·노드 150 상한).
- 들어가지 않는 것: 본문·이름·소개·밴드명·주소·글 번호·서비스 ID·사진·파일명·원래 날짜와 시각·클래스 이름·속성 원문·예외 메시지 원문·해시.
- 자동으로 보내지 않음. 미리보기에 보이는 문자열과 저장 파일이 같음. 최근 작업 3개·5MB·7일까지만 보관, 지워도 모은 글은 그대로.

### 진단을 받은 뒤 업데이트 절차

진단 파일 → 실패 코드·구조 표본으로 원인 분류 → 같은 구조의 **가짜 화면**을 `tests/e2e-collector/mock-band.mjs`나 `tests/unit/collector.test.ts`에 추가 → adapter(`collector/src/page/*`, `diagnostics/probes.ts`) 수정 → 기존 검사와 새 검사를 모두 통과 → 버전 올려 배포 → 사용자 화면에서 같은 진단 다시 실행.
업데이트 노트에는 어느 화면의 무엇을 고쳤는지, 합성/실제 중 어디서 검증했는지, 다시 수집이 필요한지를 적는다.

## 개발

```bash
npm run build:collector        # dist-collector/ (실제 배포용)
npm run build:collector:test   # dist-collector-test/ (가짜 밴드 서버 localhost:4588 허용)
npx vitest run tests/unit/collector.test.ts
npx playwright test --config playwright.collector.config.ts   # 확장을 실제 Chromium에 설치해 가짜 밴드에서 검사
```

수집 엔진은 수집 관리 페이지에서 돈다. 크롬이 백그라운드 서비스 워커를 수시로 종료하므로, 긴 작업을 워커에 두지 않고 모든 상태를 IndexedDB에 둔 채 페이지가 한 과제씩 처리한다(명세 3.1의 서비스 워커 역할을 이렇게 나눔).
