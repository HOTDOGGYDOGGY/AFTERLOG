# AFTERLOG Collector (밴드 수집 확장프로그램)

밴드에 로그인한 크롬에서 글·댓글을 모아 `.afterlog` 파일로 저장하는 확장프로그램. 기준 명세: 밴드수집확장 구현명세 v1.1.

## 설치 (지금은 스토어 등록 전)

1. https://hotdoggydoggy.github.io/AFTERLOG/afterlog-collector.zip 받기 → 압축 풀기
2. 크롬 `chrome://extensions` → '개발자 모드' 켜기 → '압축해제된 확장 프로그램 로드' → 푼 폴더 선택
3. 업데이트: 새 zip을 같은 폴더에 덮어쓰고 확장 카드의 새로고침(↻). 수집 중이던 작업·모은 글은 그대로 남습니다.

개발자는 `npm run build:collector` → `dist-collector/`를 로드해도 됩니다.

## 쓰는 법

밴드 화면 왼쪽 아래에 **AFTERLOG 막대**가 뜹니다. 화면마다 버튼이 다릅니다(선택 수집 명세 v1.0 6절).

| 열린 화면 | 버튼 |
|---|---|
| 글 | **이 글 저장**(열린 탭을 이동시키지 않고 읽기만) · 골라서 저장… |
| 밴드 홈·글 목록 | **이 밴드 글 전체 저장** · 골라서 저장… |
| 인물(멤버) 화면 | **이 인물의 글** · 댓글만 · 댓글 단 글까지 · 이 프로필 저장 · 골라서 저장… |
| 인물 프로필 화면 | **이 프로필 저장** · 이 인물의 글 · 댓글만 · 댓글 단 글까지 · 골라서 저장… |
| 프로필 팝업(주소 그대로) | **이 프로필 저장**(그 탭의 팝업을 그대로 읽음) · 골라서 저장… |
| 인물 댓글 목록 | **이 댓글 목록 저장** · 연결된 원글까지 · 골라서 저장… |
| 검색 결과 | **이 검색 결과 저장** · 검색 조건 수정… |

'골라서 저장…'은 수집 관리의 새 수집 화면을 그 주소로 채워 엽니다(바로 시작하지 않음). 같은 작업을 또 누르면 진행 중인 작업으로 연결합니다.

### 인물·검색 선택 수집

밴드 전체를 먼저 훑지 않고, 필요한 글만 찾아 엽니다. 네 가지를 골라 섞을 수 있고 같은 글은 한 번만 저장하며, 왜 대상이 됐는지(사유)를 모두 남깁니다.

| 모드 | 찾는 곳 | 저장 |
|---|---|---|
| 이 인물이 쓴 글 | 인물 작성글 목록 | 글 + 그 글의 전체 댓글 |
| 이 인물이 쓴 댓글만 | 인물 작성댓글 목록 | 목록에 보이는 댓글 그대로(원글은 목록의 발췌만). 다른 사람의 글·댓글 전문은 넣지 않음 |
| 이 인물이 댓글 단 글 | 인물 작성댓글 목록 → 항목을 눌러 원글 확인 | 원글 + 다른 인물 포함 전체 댓글 |
| 검색어가 들어간 글 | 사용자가 밴드에서 연 검색 결과 화면(주소 여러 개 가능, 주소마다 검색어를 읽어 채우고 행별로 고침) | 글을 열어 본문(선택 시 댓글)에서 **그 글을 찾은 주소의 검색어**로 다시 확인한 글(주소끼리는 합집합, 공통 필터는 선택) |

- 인물은 이름이 아니라 **밴드 멤버 식별자**(인물 화면 주소의 member/… 부분)로 구분합니다. 한 계정을 여러 캐릭터가 쓰면 계정 기준으로 모입니다.
- 인물 댓글 목록 항목에는 원글 주소가 없어서, 항목의 원글 발췌를 **눌러** 레이어로 열린 원글의 번호를 읽고 닫습니다. 체크박스는 누르지 않고, 아무것도 쓰지 않습니다. 같은 발췌의 원글을 이미 찾았으면 누르지 않고 저장본의 댓글과 대조합니다(대조 실패면 그 댓글만 다시 확인).
- 기간 기준: 쓴 글은 글 작성일, 쓴 댓글·댓글 단 글은 **이 인물의 댓글 날짜**(1월 글에 9월 댓글 → 9월 기간에 포함), 검색은 일치한 본문(글)·댓글의 작성일. 날짜를 모르면 빼지 않고 '판단 불가'로 둡니다.
- 검색어: 대소문자 무시·NFC 정규화 후 포함. 띄어쓰기·조사·유사어는 넓히지 않음. '모두 포함'은 같은 본문 또는 같은 댓글 안에서, 제외어가 있는 본문·댓글은 일치로 보지 않음. 인물 이름·소개에만 있는 단어는 일치가 아님. 불러오지 못한 댓글이 있으면 댓글 검색은 '판단 불가'.
- 조건 조합: 기본 **하나라도 맞으면(합집합)**. '모두 맞아야(교집합)'는 모든 조건의 후보를 다 찾은 뒤 모든 조건에 든 글만 엽니다. 댓글만(B)을 함께 고르면 결과에 든 원글에 달린 댓글만 남깁니다.
- 조건에서 빠진 글도 저장본은 남겨 두어, 나중에 다른 조건으로 대상이 되면 다시 열지 않고 다시 판정합니다(결과 파일에는 넣지 않음).
- 검색 결과 주소 형식·검색 화면 구조는 실제 밴드에서 확인하지 못했습니다. 자동으로 검색어를 넣지는 않고, 사용자가 연 검색 결과 화면에서 시작합니다.

### 인물 프로필 저장
- 프로필 화면의 **이 프로필 저장**은 스토리를 끝까지 불러온 뒤, 스토리마다 상세를 **읽기 전용으로 열어** 전문·스토리 표정 수·댓글을 읽고('이전 댓글'류 버튼만 눌러 펼침) 닫습니다. 하트·표정짓기·답글쓰기·메뉴(차단·신고)·입력칸은 누르지 않습니다. 보이는 모습 그대로의 **보관 당시 화면**도 함께 둡니다.
- 멤버 목록 등에서 주소가 바뀌지 않고 뜨는 **프로필 팝업**은 저장 막대가 알아봅니다. 팝업·멤버 목록에는 인물 식별자가 없어서, 기본 정보를 읽은 뒤 팝업의 **'스토리 보기'(없으면 '작성글 보기')만 눌러** 바뀐 주소로 인물을 알아내고 사용자 화면은 되돌립니다. 그 뒤 수집 창에서 그 인물의 프로필 화면 전체와 '사진' 탭을 모읍니다. 인물 작성글·사진·댓글 화면 위의 팝업은 이름이 머리글과 같으면 누르지 않고 그 인물로 봅니다.
- 인물 화면 **'사진' 탭**: 끝까지 스크롤해 이 인물이 올린 사진을 원본 주소(+ 목록 축소본)로 받습니다. 사진은 누르지 않습니다.
- 구조 자료는 앱과 같은 해석기(`src/importers/band/profile.ts`, 형식 `afterlog.band-profile/1`)로 만듭니다. 화면에 숫자가 없으면 0이 아니라 '확인 못 함', 스토리 0개 확인/수집 안 함/확인 못 함을 구분합니다.
- 아직: 프로필 사진 이력(화면 표본 없음 → '확인 못 함'), 반응자 목록. 스토리 댓글 항목 구조와 '이전 댓글' 동작은 표본에 댓글이 없어 일반 글 댓글 구조를 가정했고 실제 밴드에서 미검증입니다.

### 직접 열며 수집
- 밴드 화면 막대의 **직접 열며 수집**을 누르면 수집 관리 창이 열리고, 그 탭에서 사용자가 여는 화면(프로필 팝업·프로필 화면·스토리 상세·인물 '사진' 탭)을 바뀔 때마다 그대로 읽어 한 인물 아래에 보탭니다. 확장은 누르거나 스크롤하지 않습니다.
- 첫 화면의 인물이 대상입니다. 다른 인물·밴드 화면, 이름만 같고 식별되지 않는 팝업은 저장하지 않고 '범위 밖'으로 알립니다. 같은 내용은 다시 늘리지 않습니다.
- 자동 수집이 막히는 화면(예: 스토리가 늦게 뜨거나, 상세를 자동으로 열지 못함)을 직접 열어 채우는 용도입니다. 게시글은 막대의 '이 글 저장'을 씁니다.

### 보관 파일 가져오기
- 수집 관리 왼쪽 **보관 파일 가져오기**로 사이트·로컬 실행판·확장이 만든 .afterlog(여러 파트는 함께)를 엽니다. 바로 수집하지 않고 글·댓글 모음·프로필 목록을 보여 주며, 각 항목을 눌러 HTML로 봅니다.
- **부족한 자료 이어 수집**: 댓글이 모자란 글·실패한 글·스토리를 다 못 모은 프로필만 새 작업으로 다시 엽니다. 원래 주소가 없는 옛 자료는 열람만 됩니다.

### 속도

- 목록용·글용 수집 창을 따로 열어, 목록을 다 훑기 전에도 찾은 글부터 저장합니다. 요청 간격(1.5~3초)은 두 창이 함께 지키고, 앞 요청을 **시작한 때부터** 잽니다(준비를 기다린 시간만큼 또 기다리지 않음).
- 이미지는 본문을 저장한 뒤 뒤에서 받습니다(다음 글을 막지 않음). 같은 이미지 주소는 진행 중인 요청과도 합쳐 한 번만 받습니다.
- 이미 저장한 글은 다시 열지 않고 저장본을 재사용해 이번 파일에 넣습니다('이전 저장본 재사용' 표시). 끄면 모두 다시 엽니다.
- 수집 중에는 글 하나당 걸린 시간과 남은 예상 시간을 보여 줍니다. 위쪽에 저장한 글·댓글 합계가 나옵니다.
- 댓글을 다 못 받은(일부) 저장본은 재사용하지 않고 다시 엽니다.

### 공통

| 하고 싶은 것 | 방법 |
|---|---|
| 주소 여러 개·기간 | 확장 아이콘 → **수집 관리 열기** → 새 수집 |
| 수집한 글 확인 | 수집 관리의 글 제목을 **한 번** 누르면 저장한 전체 내용, **두 번** 누르면 밴드에서 원래 글이 열립니다(메모 칸의 '밴드에서 열기 ↗'도 같음) |
| 바로 읽기 | 수집 관리 → **HTML로 저장**. 글 하나면 HTML, 여러 개면 목차(index.html)와 글별 HTML ZIP. 인터넷 없이 열림 |
| 결과 보기 | 수집 관리 → **.afterlog로 저장** → AFTERLOG 사이트나 로컬 실행판의 '파일 열기'(첫 화면 버튼·끌어다 놓기·프로젝트 메뉴 어디서나, 여러 파트면 모두 함께 선택) |

- ×로 막대를 숨기면 그 탭에서는 작은 'AFTERLOG 저장' 버튼만 남습니다. 막대는 페이지 내용을 읽지 않고, 밴드 페이지의 스크립트가 흉내 낸 클릭은 무시합니다.
- 수집 관리 창을 닫으면 멈추고, 다시 열어 **이어받기**하면 모은 글·댓글 관측은 그대로 두고 남은 것만 이어서 합니다.
- 같은 오류가 서로 다른 글에서 3번 연속 나거나, 로그인이 풀리거나, 처음과 다른 계정으로 보이면 멈추고 이유를 보여 줍니다.

## 권한

| 권한 | 이유 |
|---|---|
| `scripting` | 밴드 화면에서 게시글 영역을 읽기 위해 |
| `unlimitedStorage` | 모은 글·이미지를 브라우저에 보관하기 위해 |
| `https://band.us/*`, `https://www.band.us/*` | 밴드 화면만(저장 막대도 이 주소에서만 뜸) |
| `https://*.pstatic.net/*` | 밴드 이미지 파일 받기 |

모든 사이트 접근·탭 목록·쿠키·다운로드 권한은 쓰지 않습니다. 글쓰기·댓글·표정 누르기 같은 동작은 코드에 없습니다.

## 무엇을 저장하나

- 게시글 카드(`.cPostCard`, 없으면 작성자 영역으로 찾은 게시글 범위) 영역의 DOM 조각만. 옆 메뉴·밴드 소개 같은 바깥 영역은 넣지 않음. 스크립트·이벤트 속성은 지우고 이미지 주소는 절대 주소로 바꿈. 배경 화면·로그인 정보·쿠키는 복사하지 않음.
- 이미지: 받은 바이트가 실제 이미지인지 확인(로그인 화면 HTML을 이미지로 저장하지 않음). `?type=s75` 같은 축소본은 '축소본만'으로 표시.
- 보고서(`capture/report.json`): 목록 끝 판정, 글별 상태, 표시 댓글 수 대비 확보 수, 이미지 실패, 아직 못 하는 것.

## 문제 진단 (개발자에게 보낼 파일)

수집 관리 → 작업 → **문제 진단** → **진단 내용 보기** → 확인 → **진단 파일 저장** (`AFTERLOG_diagnostic_v1.json`).

- 허용 목록 방식: `collector/src/diagnostics/schema.ts`에 선언된 키·열거값·구간만 들어감. 정의되지 않은 키나 자유 문자열이 있으면 저장 자체를 막음(`serializer.ts`). 한글·주소·메일·긴 숫자·토큰 모양이 보이면 한 번 더 막음.
- 들어가는 것: 확장·해석기 버전, 브라우저 종류와 주 버전, 화면 너비 구간, 단계별 상태(화면 인식, 알려진 위치 발견 개수 구간, 필드 있음/없음, 답글 연결, 댓글 수 일치, 첨부 실패 코드, 목록 진전 여부), 대기 시간 구간, 실패한 화면의 **구조 표본**(태그 종류·표준 역할·알려진 위치 ID·텍스트 있음 여부만, 반복 행은 하나로 축약, 깊이 8·노드 150 상한).
- 들어가지 않는 것: 본문·이름·소개·밴드명·주소·글 번호·서비스 ID·사진·파일명·원래 날짜와 시각·클래스 이름·속성 원문·예외 메시지 원문·해시.
- 자동으로 보내지 않음. 미리보기에 보이는 문자열과 저장 파일이 같음. 최근 작업 3개·5MB·7일까지만 보관, 지워도 모은 글은 그대로.

### 진단을 받은 뒤 업데이트 절차

진단 파일 → 실패 코드·구조 표본으로 원인 분류 → 같은 구조의 **가짜 화면**을 `tests/e2e-collector/mock-band.mjs`나 `tests/unit/collector.test.ts`에 추가 → adapter(`collector/src/page/*`, `diagnostics/probes.ts`) 수정 → 기존 검사와 새 검사를 모두 통과 → 버전 올려 배포 → 사용자 화면에서 같은 진단 다시 실행.
업데이트 노트에는 어느 화면의 무엇을 고쳤는지, 합성/실제 중 어디서 검증했는지, 다시 수집이 필요한지를 적는다.

## 개발

```bash
npm run build:collector        # dist-collector/ (실제 배포용)
npm run build:collector:test   # dist-collector-test/ (가짜 밴드 서버 localhost:4588 허용)
npx vitest run tests/unit/collector.test.ts
npx playwright test --config playwright.collector.config.ts   # 확장을 실제 Chromium에 설치해 가짜 밴드에서 검사
```

수집 엔진은 수집 관리 페이지에서 돈다. 크롬이 백그라운드 서비스 워커를 수시로 종료하므로, 긴 작업을 워커에 두지 않고 모든 상태를 IndexedDB에 둔 채 페이지가 한 과제씩 처리한다(명세 3.1의 서비스 워커 역할을 이렇게 나눔).

## 문제 해결

| 증상 | 원인·대처 |
|---|---|
| 글 찾기는 되는데 '대기'에서 안 넘어감 (0.1.1 이하) | 목록 끝의 '불러오는 중' 표시를 너무 넓게 잡아 목록 찾기가 끝나지 않던 문제. 0.1.2에서 화면 아래쪽에 실제로 보이는 로딩만 기다리고, 새 글이 안 나오면 멈춥니다 |
| '표시된 댓글 228개 중 72개' 같은 일부 확보 (0.2.0 이하) | 밴드가 댓글을 나눠 보여 줌. 0.2.1부터 댓글 영역의 '이전 댓글 · 댓글 더보기 · 답글 N개 보기'류 버튼만 눌러 불러옴(쓰기·표정·번역·숨기기·신고는 누르지 않음). 기존 작업은 '댓글 모자란 글 다시'. 그래도 모자라면 진단 파일을 보내 주세요(버튼을 찾았는지 기록됨) |
| 모든 글이 '게시글을 찾지 못했습니다' (0.1.2 이하) | 목록에서 레이어로 연 글에는 게시글 카드(`.cPostCard`)가 있지만, 글 주소를 바로 열면 그 표시가 없는 화면이 나옴. 0.1.3부터는 작성자 영역에서 위로 올라가 작성자 영역 하나와 댓글(없으면 본문)을 품는 가장 가까운 영역을 게시글로 씀. 여러 개라 못 고르면 추측하지 않음 |
| `Frame with ID 0 was removed` | 크롬이 뒤쪽 수집 탭을 정리(메모리 절약)했거나 페이지가 새로 고쳐진 경우. 0.1.2부터 수집 탭은 정리 대상에서 빼고, 이런 오류는 2번까지 다시 시도합니다. 목록 단계에서 끊기면 그때까지 찾은 글부터 수집하고 '일부'로 표시합니다 |
